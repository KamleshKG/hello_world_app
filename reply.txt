
As part of the Horizon CICD platform migration, we are integrating the existing pipeline with Cloud Pega using OAuth 2.0 authentication (replacing the current Basic Auth / PRPC wrapper approach).

Our team has completed a proof-of-concept validating the OAuth2 client_credentials flow against a Pega Community Edition instance. The pipeline-side OAuth shared library is ready. To proceed with the actual Cloud Pega integration, we require the following details from your team:

─────────────────────────────────────
MANDATORY — Cannot proceed without these
─────────────────────────────────────

1. Cloud Pega Tenant URL (Base URL)
   The publicly resolvable hostname of your Cloud Pega environment.
   Example: https://<tenant>.pegacloud.io  or  https://pega.yourbank.com
   ► Without this, the pipeline cannot reach the Pega server.

2. OAuth2 Token Endpoint
   The full URL of the token endpoint on your Cloud Pega instance.
   Standard pattern: https://<tenant>/prweb/PRRestService/oauth2/v1/token
   Please confirm if this differs on your environment.
   ► Without this, no Bearer token can be obtained.

3. Client ID
   The OAuth2 Client ID generated from the OAuth 2.0 Client Registration in Pega Dev Studio (Security → OAuth 2.0 Client Registration).
   ► Without this, the token request cannot be constructed.

4. Client Secret
   The corresponding Client Secret for the above Client ID.
   Please share via secure channel (vault / encrypted mail / secret manager).
   ► Without this, the client_credentials grant cannot be authenticated.

5. Operator ID mapped to the OAuth Client Registration
   The Pega Operator ID assigned to the OAuth client (used as the effective permission context for all API calls made by the pipeline).
   This operator must have access rights to the Import and Export APIs.
   ► Without this, API calls will fail with authorization errors even if token is obtained.

─────────────────────────────────────
IMPORTANT — Required to avoid integration failures
─────────────────────────────────────

6. Access Group / Permissions
   Confirm the Operator mapped to the OAuth client has the following API access:
   • Pega Import API  (/prweb/api/v1/archives  or equivalent)
   • Pega Export API  (/prweb/api/v1/archives  or equivalent)
   • Any additional role or privilege required for deployment operations.

7. Network / Firewall Whitelisting
   Confirm whether inbound API calls from our CICD pipeline infrastructure require IP whitelisting or VPN connectivity on the Cloud Pega side.
   If yes, please share the process to get our pipeline egress IPs whitelisted.

8. Token Expiry and Refresh Policy
   Confirm the access token TTL (default is typically 3600 seconds).
   Confirm whether refresh tokens are issued or whether a new token must be obtained per pipeline run.

─────────────────────────────────────
GOOD TO HAVE — For production readiness
─────────────────────────────────────

9. Environment Details
   Confirm which environments are available and their respective tenant URLs:
   • DEV
   • SIT / QA
   • UAT
   • PROD
   Each environment will need its own Client ID and Secret.

10. Pega Version
    Confirm the Pega Platform version running on Cloud (e.g. Infinity 26.x, 24.x, 8.x).
    This ensures API path compatibility with our PRPC wrapper.

11. SSL / TLS Certificate
    Confirm whether the Cloud Pega tenant uses a standard public CA-signed certificate or a custom/internal CA.
    If internal CA, we will need the certificate chain for our pipeline trust store.

─────────────────────────────────────

─────────────────────────────────────
ADDITIONAL MANDATORY — Import/Export API specific
─────────────────────────────────────

12. Confirm Import/Export API endpoints on Cloud Pega
    Standard: 
      POST /prweb/PRRestService/SystemManagement/v2/Import
      POST /prweb/PRRestService/SystemManagement/v2/Export
    Confirm if these paths differ on your Cloud tenant.
    ► Our pipeline PRPC wrapper calls these directly.

13. Confirm SystemManagement Service Package is OAuth2-protected
    On Cloud Pega Dev Studio → Service Packages → SystemManagement
    → Authentication type must be set to OAuth 2.0 (not Basic Auth).
    ► If still set to Basic, Bearer token will be rejected with 401
      even if token acquisition succeeds.
    ► This is a Cloud Pega admin change — please confirm or action.

14. Confirm API version compatibility
    Our current wrapper targets SystemManagement v2 endpoints.
    Pega Infinity 26.x may have updated API paths.
    Please confirm the correct version path on your environment.

Good question — this is a shared responsibility. Let me break it down clearly.

The Network Flow:

Your Lab Jenkins VM          Cloud Pega
(192.168.56.x)          →   (*.pegacloud.io)
     │
     │  This outbound call crosses:
     │  1. Your Lab/Bank network firewall
     │  2. Internet
     │  3. Pega Cloud firewall/WAF
     │
     └──► POST /oauth2/v1/token
          POST /SystemManagement/v2/Import

Two separate firewall problems — two separate owners:

Problem 1 — Your side (BofA/Lab network)

Jenkins pipeline VM sits inside BofA network
BofA network firewall may block outbound HTTPS to *.pegacloud.io
Owner: BofA Network/Infra team
Action: Raise a firewall change request to allow outbound port 443 from Jenkins egress IPs to Cloud Pega tenant URL

Problem 2 — Pega Cloud side

Cloud Pega may have IP whitelisting on inbound — only allowing known IPs in
Unknown IP from your Jenkins = Connection Refused or 403
Owner: Pega Cloud admin / LOB who manages the Cloud Pega tenant
Action: They need to whitelist your Jenkins egress IPs on the Cloud Pega WAF/firewall

What you need to provide to each:

To BofA Network team:

Request Type : Firewall outbound rule
Source       : Jenkins pipeline server IPs
Destination  : <Cloud Pega tenant URL> port 443
Protocol     : HTTPS
Purpose      : CICD pipeline deployment to Cloud Pega

To LOB/Cloud Pega team:

Request Type : Inbound IP whitelist on Cloud Pega
IPs to allow : <Jenkins server egress IPs>
Endpoints    : /prweb/PRRestService/oauth2/v1/token
               /prweb/PRRestService/SystemManagement/v2/Import
               /prweb/PRRestService/SystemManagement/v2/Export
Purpose      : CICD pipeline OAuth2 + deployment API access

How to get Jenkins egress IPs:

Run this from your Jenkins server:

bash
curl -s https://ifconfig.me
# or
curl -s https://api.ipify.org

That's the public IP Pega Cloud will see incoming from your pipeline.

In short:

BofA Network team → outbound rule from Jenkins
LOB/Pega Cloud admin → inbound whitelist on their side
You → provide the Jenkins egress IPs to both
